## D-01. 향수 시장을 선택 (2026-10-06)
- **결정:** 화장품이 아닌 향수 도메인에서 서비스를 만든다.
- **배경:** 뷰티 PM 관점의 메이커톤 과제. 화장품 서비스는 이미 고도화되어 있다.
- **이유:**
  - 국내 향수 시장 2025년 1조 1,180억 원(+6.7%), 2028년 1조 3,570억 원 전망 (유로모니터, 한국경제 2026.01.17)
  - 프리미엄 향수 2019~2024 연평균 12.6% 성장, 니치 향수 매출 +17%, 29CM 향수 거래액 25년 4분기 +84% (나스미디어 2026.02.02)
  - 구매 최우선 기준 "향이 내 취향에 맞는지" 67.9% (오픈서베이 2025) → 취향은 직접 맡아봐야만 확인 가능
- **다른 선택지:** 화장품 성분·피부 타입 서비스 (경쟁 과다로 제외)

## D-02. 문제 정의를 "뭘 맡아봐야 할지 모르는 막막함"으로 확정 (2026-10-07)
- **결정:** 향수를 사거나 선물하려는 사람은 직접 맡아봐야 확신하지만, 원하는 향을 말로 설명하지 못해 무엇을 맡아볼지 정하지 못하고 직원 추천이나 인기 제품에 기대 후보를 고른다. 이 막막함을 당연하게 넘기는 사이, 맞지 않아 쓰지 않는 향수가 서랍에 쌓인다.
- **배경:** 공개 자료 → 커뮤니티 리서치 → 가설 문제 정의 → 설문(21명) 순서로 구체화.
- **이유 (자체 설문 2026.10.06~07, 구매 경험자 21명):**
  - "직접 맡아볼 수 있어서" 시향을 가장 신뢰 81%
  - "말로 설명 어려움" 또는 "뭘 맡아야 할지 모름" 67%
  - 설명해 본 20명 중 "잘 통했다" 0명
  - 후보를 찾을 때 남의 판단 의존 86% (직원 추천 62%)
  - 안 쓰는 향수 1개 이상 86%, 그중 "서랍에 그대로" 52%
  - 불편 정도 4점 48%, 5점 0명, 1~2점 43% → "불편하지만 당연하게 넘기는 문제"로 정의
- **다른 선택지:**
  - "시향지 첫 향 ≠ 잔향" 문제 (커뮤니티 근거는 강했지만 공식 근거가 약하고, 해결책인 시간대별 트래킹이 박람회 시연에 불리)
  - 중고 향수 가품 체크 (공식 근거는 가장 강했지만 사용자가 원하는 방향과 다름)
  - 분사량·향 매너, 구매처 가격 비교 (근거 약함)

## D-03. 타겟을 경험 수준이 아닌 "상황"으로 정의 (2026-10-06)
- **결정:** "향수 입문자"가 아니라 "향수를 사거나 선물하려고 시향을 앞둔 사람".
- **이유:** 입문자는 취향을 몰라서, 경험자는 아는 향도 피부에서 달라서 실패한다. 원인은 달라도 실패가 일어나는 순간(시향 직후~구매 결정 전)은 같다.

## D-04. "구매 추천"이 아니라 "시향 후보 추천" (2026-10-07)
- **결정:** 결과 문구는 "이 향수를 사세요"가 아니라 "이 순서로 맡아보세요".
- **이유:** 81%가 직접 맡아보기를 가장 신뢰한다. 추천이 틀려도 실패 비용이 없고, 사람들이 믿는 방식(직접 시향)을 존중한다. 기존 AI 추천 서비스(어코다, 퍼라 등)와의 차별점.
- **다른 선택지:** 구매 추천 + 쇼핑 링크 (경쟁 과다, 신뢰 문제)

## D-05. 후보는 3개 (2026-10-06)
- **결정:** 한 번에 시향 후보 3개.
- **이유:** 매장 시향 팁("한 번에 3~4개만")과 설문의 "후보가 너무 많아 뭘 맡아야 할지 몰랐다" 38%. 선택지를 좁히는 것 자체가 가치.

## D-06. 시향 순서와 시향 팁을 핵심 기능에 포함 (2026-10-07)
- **결정:** 3개를 가벼운 향 → 진한 향 순으로 자동 정렬하고, 공통 시향 팁과 향수별 체크 포인트를 보여준다.
- **이유:** 진한 향을 먼저 맡으면 코가 둔해진다. "잔향 맡아보고 올게요" 팁에 커뮤니티 공감 157. 다른 추천 서비스에 없는 정보.

## D-07. 잔향 트래킹은 다음 단계로 미룸 (2026-10-06)
- **결정:** MVP에는 시향 메모(별점 + 한 줄)만 넣고, 시간대별 잔향 트래킹은 "준비 중"으로 안내한다.
- **이유:** 1~4시간 기다려야 결과가 나와 박람회 시연이 어렵고, 문제 정의(시향 전 막막함)와 다른 문제를 푼다. 메모가 트래킹의 씨앗 역할.
- **다른 선택지:** 잔향 예보(노트 데이터 기반 시간대 예측) → "내 피부에서의 변화"를 알려주지 못해 문제 해결이 안 됨, 제외

## D-08. 입력은 일상어 칩, 분위기와 향기 대상을 분리 (2026-10-07)
- **결정:** self 모드는 분위기(형용사) → 향기 대상(명사) → 피하고 싶은 느낌, gift 모드는 그 사람의 분위기 → 피하고 싶은 느낌 + "잘 모르겠어요".
- **이유:** 설문 주관식에서 사람들은 "차분한, 깨끗한"(분위기)과 "비누, 숲 냄새, 풀향기"(대상)를 섞어 썼다. 선물 시 41%가 "몰라서 무난한 인기 제품"을 고름 → "잘 모르겠어요"는 호불호 적은 향 위주로.
- **칩 우선순위:** 설문 상위 차분한(8), 깨끗한·시원한·포근한(7), 싱그러운(5). 숲·나무 표현 4회 → 향기 칩에 포함.

## D-09. 향 계열 14개 (2026-10-07)
- **결정:** 시트러스, 프루티, 아쿠아·오존, 그린, 아로마틱, 플로럴, 화이트 플로럴, 파우더리, 머스크·클린, 스파이시, 우디, 앰버, 구르망, 레더·스모키. 번호 = 시향 순서.
- **이유:** 7개로는 다양한 취향을 담기 부족하다는 피드백. 향수 업계의 일반적인 향 분류를 참고해 세분화.

## D-10. 서비스 이름 "시향노트 / SCENT NOTE" (2026-10-07)
- **결정:** 한국어 시향노트, 영어 SCENT NOTE.
- **이유:** '노트' = 향수의 노트 + 나의 시향 기록. 한국어·영어 모두 향수 서비스임이 바로 드러난다. 맡기 전(노트 읽기) → 맡는 동안(순서대로) → 맡은 후(기록)를 하나로 잇는다.
- **검토한 이름:** 맡아볼래, 시향길(숲 색이 특정 취향에 치우침), 블로터(IT 매체명과 겹침), 노트랩(향수와 연결 약함), 센트맵(국내 향수 브랜드 존재), 센트픽(일본 향수 구독명), 노트디센트(불어·영어 혼용, 'decent'로 읽힘)

## D-11. 디자인: 미드나잇 잉크 + 향 계열 색은 "면"으로 (2026-10-07)
- **결정:** 글자·버튼은 미드나잇 잉크 `#231F3A`, 바탕 페이퍼 `#F8F6F3`, 향 계열 색은 선택 칩·카드 배경·상단 띠 등 면으로 사용. 폰트 IBM Plex Sans KR + IBM Plex Mono.
- **이유:** 네이비의 신뢰감은 유지하되 순수 네이비는 금융 앱처럼 보여 향수 느낌이 약했다. 보랏빛 잉크로 깊이를 더하고, 고른 취향에 따라 화면 색이 바뀌게 해 정적이지 않게.
- **다른 선택지:** 숲 초록 메인(특정 취향에 치우침), 크림+탠저린(가벼움), 화이트+라일락(정보 서비스 느낌 약함)

## D-12. 가격은 공식 정가만 (2026-10-07) → D-18에서 보완
- **결정:** 정가 + 용량 + 기준일 + "가격은 변동될 수 있어요". 최저가·쇼핑 링크 없음.
- **이유:** 1회 평균 구매액 12만 원대로 가격은 시향 여부를 정하는 중요한 정보. 최저가는 매일 변하고 가품 위험(가품 화장품 상담 중 향수 51.5%)과 얽힌다.

## D-13. 매장 찾기는 지도 검색 링크로 (2026-10-06)
- **결정:** 네이버 지도 검색 결과로 연결.
- **이유:** 위치 기반은 지도 API·매장 입점 데이터가 필요하고 정확도를 유지하기 어렵다. 24%가 "시향하러 가기 번거로웠다"고 답해 기능 자체는 필요.

## D-14. 기술: 정적 웹 + localStorage, Vercel 배포 (2026-10-07) → D-17에서 데이터 출처 변경
- **결정:** React + Vite + TypeScript + Tailwind, 데이터는 정적 JSON, 메모는 localStorage, Vercel 배포.
- **이유:** 바이브 코딩으로 일주일 안에 만들고, 박람회까지 고정 URL을 안정적으로 유지해야 한다. 서버·로그인이 없으면 실패 지점이 줄어든다.

## D-15. 이미지·저작권 원칙 (2026-10-06) → D-17에서 변경
- **결정(당시):** 향수병 사진, 브랜드 로고, 외부 리뷰 원문을 쓰지 않는다. 향 설명 문구는 직접 쓴다.
- **변경:** 향수 API가 제공하는 병 이미지는 사용 가능(D-17). 브랜드 로고·외부 리뷰 원문 금지, 일상어 설명 직접 작성은 유지.

## D-16. 커버·로고 이미지는 서비스 완성 후 제작 (2026-10-07)
- **결정:** 바이브 코딩으로 서비스를 먼저 만든 뒤, 실제 화면을 보고 커버(380×270)·프로젝트명(150×100) 이미지를 만든다.
- **이유:** 상상으로 만든 시안이 원하는 느낌과 달랐다. 실제 화면과 이미지가 일치해야 신뢰감이 생긴다.
- **주의:** 노션 제출 마감 10/13(화) 21:00. 늦어지면 임시 이미지 제출 후 운영진에 교체 요청.

## D-17. 외부 향수 API로 데이터·이미지 가져오기 (2026-10-07) → D-21에서 폐기
- **결정:** 향수 정보(노트·어코드·계절·이미지·해외 가격)는 외부 향수 API에서 가져온다. 1순위 후보는 Fragella API. 향수병 이미지는 API가 제공한 것만 쓰고 출처를 표시한다.
- **이유:** 30개 향수의 노트를 사람이 일일이 옮기는 것보다 정확하고 빠르며, 병 이미지가 있으면 매장에서 실물을 찾기 쉽고 결과 화면이 훨씬 향수 서비스답다.
- **방식:** 앱이 API를 실시간으로 부르지 않고, `npm run sync`로 미리 받아 `perfumes.raw.json`에 저장 → 앱은 JSON만 읽는다. 한국어 설명·국내 정가는 `perfumes.ko.json`에 직접 작성해 병합.
  - 무료 플랜 한도가 작다(Fragella 무료 월 20회)
  - 박람회 당일 API 장애·한도 초과에도 서비스가 동작해야 한다
  - API 키가 브라우저에 노출되지 않는다
- **주의:** 이용약관에서 이미지 표시·캐싱·출처 표기 조건을 확인해 여기에 기록한다. 웹사이트 스크래핑(Fragrantica·Parfumo 등)은 하지 않는다.
- **다른 선택지:** 전부 수동 입력(느리고 오류 가능), 브라우저 실시간 호출(키 노출·한도 문제), 스크래핑(약관 위반 소지)

## D-18. 가격: 국내 정가 우선, API 가격 보조 (2026-10-07)
- **결정:** ① 국내 공식몰에서 확인한 원화 정가(기준일·출처) → ② 없으면 API의 해외 가격을 원래 통화 그대로 "해외 기준가"로 표시 → ③ 둘 다 없으면 "[확인 필요]". 항상 "가격은 변동될 수 있어요".
- **이유:** 가격은 시향하러 갈지 판단하는 중요한 정보(1회 평균 구매액 12만 원대). 해외 API 가격은 국내 가격과 다를 수 있어 원화로 바꾸지 않고 출처를 밝힌다. 최저가 비교·구매 링크는 여전히 하지 않는다(시향 후보 추천 원칙, 가품 위험).

## D-19. 시향 후보 카드를 앞면/뒷면 뒤집기 카드로 (2026-10-07)
- **결정:** 앞면 = 향수 정보(이미지·계열·이름·노트 막대·요약·추천 이유·가격), 뒷면 = 시향 가이드(노트 성분·일상어, 잔향, 강도, 호불호, 계절·상황, 체크 포인트, 매장 찾기·메모 버튼). 메모는 뒷면 버튼 → 팝업.
- **이유:**
  - 카드 3장을 펼침 방식으로 열면 화면이 길어지고 시향 순서가 한눈에 안 보인다. 뒤집기는 카드 크기가 유지돼 3장 비교가 쉽다.
  - "맡으러 갈지 판단(앞)" → "매장에서 어떻게 맡을지(뒤)"로 정보의 쓰임이 나뉜다.
  - 시향지를 뒤집어 보는 경험과 이어지고, 박람회 시연에서 눈에 띄는 인터랙션이 된다.
- **보완:** 노트를 쉬운 말로 설명하는 게 핵심 가치이므로 앞면에 노트 색 막대 + 일상어 요약을 유지한다. gift 모드에서는 "호불호 적음"을 앞면 배지로도 보여준다. 가격 기준일은 앞면 가격 바로 아래에 둔다. 첫 카드에 1회 힌트 모션으로 뒤집을 수 있음을 알린다.
- **다른 선택지:** 아래로 펼치기([자세히 보기]) — 구현은 쉽지만 3장 비교와 시연 임팩트가 약함

## D-20. 모바일 앱이 아닌 웹 페이지로, 데스크톱 우선 반응형 (2026-10-07)
- **결정:** 첫 버전은 웹 페이지로 만든다. 데스크톱(1280~1440px)을 기준으로 디자인하고 모바일(390px)에서도 깨지지 않게 반응형으로 대응한다.
- **이유:**
  - 박람회는 ZEP에서 PC 브라우저로 접속해 링크를 연다 → 데스크톱 화면이 첫인상
  - 시향 전 집·회사에서 미리 후보를 정하는 사용 순간이 많다
  - 데스크톱에서는 시향 후보 3장을 가로로 나란히 놓아 "①→②→③ 시향 순서"가 한눈에 보인다
  - 앱 설치 없이 링크 하나로 바로 써 볼 수 있다
- **반영:** Select 화면에 실시간 "내 취향 노트" 패널, Result 카드 가로 3열, 메모는 중앙 모달. 모바일 앱 전환은 이후 단계.

## D-21. 향수 데이터는 API 없이 사람이 직접 입력한 JSON으로 (2026-10-07)
- **결정:** 외부 향수 API를 쓰지 않는다. 향수 정보는 사람이 공식 출처에서 확인해 `src/data/perfumes.json` 하나에 직접 입력한다. `perfumes.raw.json`, `accord-map.json`, `sync` 스크립트는 만들지 않는다. D-17은 폐기.
- **이유:** Fragella 무료 플랜은 월 20회로 향수 30개에 부족하다. 대안으로 본 무료 데이터셋·GitHub API(PerfumAPI 등)는 Fragrantica 스크래핑 결과라 이용약관·라이선스 문제가 있다.
- **원칙 유지:** 확인하지 못한 값은 지어내지 않고 `[확인 필요]`로 둔다. 노트·가격은 공식몰 등 직접 확인한 출처만 쓴다. 노트·향수 설명 텍스트는 웹사이트에서 스크래핑하지 않는다.
- **다른 선택지:** Fragella 무료 20개 + 직접 입력 혼합, Fragella 유료 1개월, 무료 CSV 데이터셋

## D-22. 향수병 이미지는 사람이 직접 모아 와서 쓴다 (2026-10-07)
- **결정:** 병 이미지는 사람이 직접 구해서(공식몰·브랜드 사이트 등) 프로젝트에 파일로 넣어 쓴다. 이 결정으로 기존 "API가 제공한 이미지만 쓴다" 규칙(CLAUDE.md 4번)을 바꾼다.
- **이유:** 박람회 제출용(비상업)이고, 이미지가 있어야 매장에서 실물을 찾기 쉽고 결과 화면이 향수 서비스답다.
- **위험(인지하고 감수):** 이미지 저작권은 브랜드·판매처에 있다. 비상업 데모여도 허락 없이 쓴 이미지는 문제가 될 수 있다. 박람회 이후 공개 운영하거나 상업화하면 이미지를 내리거나 허락을 받아야 한다.
- **완화 방법:**
  - 다른 사이트 URL을 핫링크하지 않고 `public/perfumes/`에 파일로 저장해 쓴다 (원본 사이트 장애·차단에 영향받지 않음)
  - 이미지를 구한 출처를 향수별로 기록하고 화면에 "이미지: 각 브랜드 공식 이미지" 같은 출처를 표시한다
  - 브랜드 로고는 쓰지 않는다 (병 이미지만)
  - 이미지가 없으면 향 계열 색 플레이스홀더로 대체
- **다른 선택지:** 이미지 없이 색 플레이스홀더만 사용(안전하지만 시각적 임팩트 약함)

## D-23. 시향 메모는 Supabase에 저장 (2026-10-07)
- **결정:** 시향 메모(별점 + 한 줄 메모)를 Supabase에 저장한다. 로그인 화면 없이 익명 로그인(`signInAnonymously`)으로 브라우저별 `user_id`를 만들고, RLS로 본인 메모만 읽고 쓰게 한다. localStorage는 캐시·장애 대비로 함께 쓴다. D-14의 "메모는 localStorage"와 CLAUDE.md 규칙 8번을 바꾼다.
- **이유:** 사용자들이 남긴 메모를 모아서 볼 수 있게 하고 싶다. 향수 데이터는 정적 JSON이라 Supabase는 메모에만 쓴다.
- **주의:** 한 줄 메모는 자유 입력이라 개인정보가 들어올 수 있어 안내 문구를 넣는다. 익명 사용자는 브라우저 데이터를 지우면 이전 메모가 연결되지 않는다.
- **다른 선택지:** localStorage만 사용(기록 수집 불가), 이메일 로그인(가입 부담)

## D-24. 이미지가 없는 향수는 향 계열 색 대체 이미지로 (2026-10-07)
- **결정:** 병 이미지가 없거나 로드에 실패하면 향 계열별 대체 이미지(`public/perfumes/placeholder/{family}.svg`, 14개 + `default.svg`)를 보여준다. 이미지가 있는 향수는 그 이미지를 쓴다. 대체 이미지는 특정 브랜드 병을 따라 그리지 않은 일반 병 모양이고, 색은 디자인 토큰(fill·tint·deep)만 사용한다.
- **이유:** 공식 한국 사이트에서 이미지를 구하지 못한 향수가 많다(99개 중 16개만 확보). 빈 칸이나 깨진 이미지 대신 같은 크기의 일관된 화면을 보여줘서 레이아웃이 흔들리지 않게 한다. 규칙 4번(이미지 없으면 향 계열 색 플레이스홀더)을 구체화한 것.
- **적용:** `<img onerror>`에서 `placeholder/{family}.svg`로 교체, 알 수 없는 계열은 `default.svg`. 대체 이미지는 `alt="향수병 이미지 준비 중"`. 확인은 `preview-images.html`.
- **다른 선택지:** 이미지 칸 숨김(카드 높이가 들쭉날쭉), 이니셜 텍스트 타일(브랜드 느낌 약함)

## D-25. 데이터 범위·가격 문구·성별 구분 (2026-10-07)
- **결정 1 (데이터 범위):** 앱에는 `perfumes-draft.xlsx`의 향수 99개를 모두 넣는다. 노트·농도가 공식 확인 전인 행은 `dataStatus`(초안/확인 완료)로 구분해 내부에 유지하고, 박람회 전에 중요한 30~50개부터 공식 확인한다.
- **결정 2 (가격 문구):** 국내 정가가 있으면 "50ml 305,000원"과 "2026.10 공식몰 기준 · 가격은 변동될 수 있어요"를 보여준다. 없으면 "가격은 매장에서 확인해 보세요"를 보여준다("확인중" 문구는 쓰지 않음). 용량은 항상 함께 표시하고, 가격 줄은 없어도 자리를 남겨 카드 높이를 맞춘다.
- **결정 3 (성별):** 남성용/여성용으로 구분하지 않는다. 취향은 분위기 칩·향 계열로 고른다. 필요하면 나중에 `marketedFor`를 데이터에 표시해 가산점으로만 쓴다.
- **이유:** (1) 확인된 향수만 쓰면 후보가 너무 적어진다. (2) "확인중"은 미완성처럼 보이고, 시향 후보 추천에는 "매장에서 확인"이라는 다음 행동이 더 자연스럽다. (3) 성별 단계는 흐름을 길게 하고 유니섹스·니치 향수 구분이 모호하며, 후보 부족을 부른다.
- **다른 선택지:** 확인된 향수만 사용, "확인중" 문구, 성별 선택 단계 추가

## D-26. 분위기 칩 2개 추가(11개 → 13개)와 Step 3 팁 문구 교체 (2026-10-07)
- **결정 1:** 분위기 칩에 **사랑스러운**(`lovely`: 플로럴·프루티·화이트 플로럴·파우더리)과 **매혹적인**(`sensual`: 레더·스파이시·앰버·화이트 플로럴·구르망)을 추가한다. 13개를 넘기지 않는다.

- **반영:** `chips.json`(변환 스크립트), 엑셀 `options` 시트와 향수 40개의 `moods`(AI 판단), Select Step 1 화면.

## D-27. 선물 모드는 spec대로 2단계(분위기 → 피하고 싶은 느낌), Figma의 근거 없는 수치는 쓰지 않는다 (2026-10-07)
- **결정 1 (단계):** 선물 모드는 spec.md대로 Step 1 "그 사람은 어떤 분위기인가요?"(+[잘 모르겠어요]) → Step 2 "피하고 싶은 느낌이 있나요?" → 결과로 간다. Figma에는 선물 Step 1만 있고 2단계 이름이 "추천 선물 숏리스트"로 되어 있었지만, 추천 로직이 피하고 싶은 칩을 쓰고 spec의 완료 기준도 2단계라서 spec을 따랐다.
- **결정 2 (수치):** Figma 선물 패널의 "95.4% SAFETY", "잔향 호감도 95% 이상", "안전 지수 상위 5%", "선물 성공 기대도" 막대, "선물 포장·패키징 가이드 제공"은 실제로 계산하거나 제공하지 않는 내용이라 쓰지 않는다. 대신 실제 데이터로 센 값("호불호 적은 향 N개 / 전체 M개")과 사실만 적는다.
- **결정 3 (동작):** [잘 모르겠어요]는 분위기 선택을 비우고 `unsure=true`로 둔다. 분위기를 고르면 `unsure`는 풀린다. 선물 모드에서는 호불호 적은 향(`polarizing: low`)에 +2, 높은 향에 −2를 주고, 결과 카드 앞면에 호불호 적은 향이면 "호불호 적음" 배지를 보여준다.
- **다른 선택지:** Figma대로 1단계만 만들고 피하고 싶은 느낌은 생략(선물받는 사람의 불호를 못 거름)

## D-28. 호불호 기준, 접근성 좋은 향수 추가, 시향 가능 채널 표시 (2026-10-07)
- **결정 1 (호불호 기준):** `polarizing`은 판매순위가 아니라 향의 특징으로 정한다. low = 가벼움~보통 강도 + 피하고 싶은 칩(단/진한/머리 아픈/꽃향 강함/스모키) 해당 없음 + 레더·스파이시·구르망이 주계열이 아님, mid = 개성은 있지만 대중적, high = 강한 구르망·레더·오우드·진한 꽃·향신료 위주. 올리브영 등 판매순위는 인기와 마케팅·가격의 영향을 받고 스크래핑이 금지(규칙 5)라 기준으로 쓰지 않는다.
- **결정 2 (향수 추가):** 백화점·올리브영에서 접근하기 쉬운 대중 브랜드 향수 15개를 추가한다(총 114개). 노트 등은 같은 AI 초안이며 공식 확인 전이다.
- **결정 3 (채널):** 시향 가능 채널(`channels`)은 브랜드 기준으로 웹 검색해 근거를 찾았고, 근거 신뢰도(높음/보통/낮음/미확인)를 엑셀 `channels_status`와 `channels` 시트에 남긴다. 앱에는 '높음/보통'만 보여주고(59개 향수), '낮음/미확인'은 후보로만 둔다. 화면에는 "브랜드 기준이에요. 가기 전에 매장에 재고를 확인해 보세요"를 함께 적는다.
- **이유:** 공식 사이트 대부분이 접속을 막아 근거가 검색 결과 요약 수준인 경우가 많다. 틀린 매장 정보로 사용자를 헛걸음시키지 않도록, 근거가 약한 채널은 앱에 보이지 않게 한다.
- **다른 선택지:** 판매순위 기준 사용, 근거 없이 일반 지식으로 모든 채널 채우기, 채널 표시 생략

## D-29. 시향 메모를 Supabase에 저장 (익명 로그인, 브라우저 캐시와 함께) (2026-10-07)
- **결정:** 메모는 localStorage에 먼저 저장하고(`storage.ts`), 서버(`memos` 테이블)에는 뒤에서 올린다. 로그인 화면 없이 익명 로그인(`signInAnonymously`)으로 브라우저별 사용자를 만들고, RLS로 본인 메모만 읽고 쓴다. 메모를 저장하지 않는 방문자는 익명 사용자가 만들어지지 않는다(저장할 때 처음 만든다).
- **동작:** 서버가 느리거나 멈춰도 앱은 그대로 동작한다. 서버에 올리지 못한 저장은 다음 방문 때(Result·Notes 화면) 다시 올리고, 지우지 못한 삭제도 다시 시도한다. 향수당 메모 1개(`unique(user_id, perfume_id)`).
- **확인:** 저장 → 서버에 1행, 다른 익명 사용자와 로그인 없는 요청은 0행, 남의 user_id로 쓰기 시도는 403, 오프라인 저장 → 온라인 복귀 후 서버 반영, 삭제 → 서버에서도 삭제까지 실제로 시험했다.
- **다른 선택지:** 서버만 사용(서버 장애 시 저장 불가), 이메일 로그인(가입 부담)

- **결정**: (1) 함께 고르기 어려운 분위기 12쌍(`MOOD_CONFLICTS`, 의미 기준 직접 지정)을 정해, 한쪽을 고르면 다른 쪽 칩을 숨기지 않고 흐리게 + 선택 불가 + 이유 한 줄로 표시한다. (2) 향수마다 대표 계열(family)을 affinity로 가진 분위기 칩을 추가한다. 강도 조건(strong은 깨끗한·시원한·싱그러운·상큼한 제외, light는 묵직한·매혹적인 제외)과 기존 태그와의 충돌 쌍 제외를 적용한다.
- **이유**: 3개를 고르면 결과가 0종인 경우가 많았다(태그 평균 3.3개). 충돌 칩을 미리 막고 태그를 늘려 빈 결과를 줄인다.
- **결과**: 태그 평균 3.3→4.3개. 선택 가능한 3칩 조합(184개) 중 결과 0종 64%→20%, 3종 미만 87%→48%, 평균 1.2→4.2종. 향수는 삭제하지 않음.
- **적용 방법**: `scripts/expand-moods.py --write`로 엑셀 `moods` 열을 갱신하고 `scripts/xlsx-to-json.py`로 JSON 재생성.
- **검토 필요**: maison-margiela-replica-beach-walk(태그 4개 추가), creed-aventus·versace-eros(strong인데 fresh 태그 보유) — 사람이 확인.

## D-31. 피하고 싶은 칩 2개 추가 + headache 재정리
- **결정**: 피하고 싶은 칩을 6→8개로 늘린다. 추가: 알싸한 향(`spicy`), 비누·세제 같은 향(`soapy`). `headache`는 규칙(strong 강도 + 화이트 플로럴 계열 또는 튜베로즈·오우드·가드니아·인센스·파출리·타바코 노트)으로 다시 태그한다.
- **이유**: 필터가 향수의 `avoidFlags`로만 작동하는데 headache는 1종, smoky는 4종뿐이었다. 호불호가 크게 갈리는 향신료·비누 향이 빠져 있었다.
- **태그 방식**: 규칙 자동 부여가 어색해서(핑크페퍼가 든 가벼운 머스크가 '알싸함'으로 분류되는 등), 향수별로 노트·강도·평판을 보고 직접 정했다(`scripts/tag-avoids.py`의 FLAGS). headache는 호불호가 큰 6종(플라워밤·엔젤·카널 플라워·블랙 오키드·에일리언·오우드 포 그레이트니스)으로 한정.
- **결과**: 알싸한 향 14종, 비누·세제 같은 향 7종, 머리 아픈 향 6종. `scripts/tag-avoids.py --write`로 엑셀 `avoid_flags` 열을 갱신하고 `xlsx-to-json.py`로 JSON 재생성. 태그는 AI 규칙 기반이라 실제 시향 확인 전 초안이다.

## D-32. 추천은 분위기·향기를 둘 다 충족하는 향수 우선 + Step 2 향기 팁 문구
- **결정**: `recommend()`가 고른 분위기(하나라도)와 고른 향기(계열·서브 계열)를 모두 충족하는 향수를 먼저 뽑고, 3개가 안 될 때만 하나만 맞는 향수로 채운다. 계열 겹침 방지·향기 칩별 1개 규칙은 각 단계 안에서 적용. 최종 순서는 기존대로 시향 순서(가벼운 향 → 진한 향).
- **이유**: 점수 합산만으로는 향기만 맞거나 분위기만 맞는 향수가 섞여(둘 다 충족 비율 74%) 사용자의 기대("둘 다 고른 대로")와 어긋났다.
- **Step 2 '향기 고르는 팁'**: 시향 순서 설명 대신 향기 고르는 방법(일상의 향기를 떠올리기)과 고른 향기별 계열·예시 향을 보여 준다.

## D-33. 향수 입문자용 "장면 고르기" 시작 경로
- **배경**: 피드백에서 "향수 입문자라 분위기를 뭘 골라야 할지 모르겠다"는 의견이 나왔다. 문제는 단계 수가 아니라 고를 기준이 없는 것이다.
- **결정**: 홈의 두 큰 버튼 아래에 보조 버튼 "향수가 처음이에요"를 두고(`/start`), 장면 카드 6장(비 온 뒤 숲길, 갓 세탁한 빨래, 한여름 바닷가, 꽃집 앞 봄날, 따뜻한 카페, 햇살 가득 과일 가게) 중 하나를 고르면 분위기 2개·향기 1개가 미리 채워져 '피하고 싶은 느낌' 단계로 간다. 채워진 칩은 이전 단계에서 바꿀 수 있다.
- **구성 기준**: 호불호가 갈리는 장면(재즈 바·스모키 등)은 뺐다. 장면 데이터는 `src/lib/scenes.ts`(칩 조합 포함), 그림은 `src/assets/images/scenes/*.svg`(일러스트, 사진으로 교체 가능).
- **검증**: 장면의 칩이 실제 칩이고 서로 어울리지 않는 분위기가 없으며, 장면마다 추천 3개 중 2개 이상이 분위기·향기를 둘 다 충족하는지 테스트로 확인.
- **보류**: 나를 위한 향수 Step 1의 "잘 모르겠어요" 추가는 아직 하지 않았다.

## D-34. 향수 98개 추가 (114 → 212), 가격·이미지는 확인된 것만 (2026-10-08)
- **결정**: 백화점·올리브영·니치 브랜드에서 98개를 추가해 총 212개로 늘렸다. 노트·농도·분류·문구는 AI 초안(공식 확인 전). 6개 작업으로 나눠 병렬로 작성하고 `scripts/add-perfumes.py`로 검증(계열·분위기 충돌·노트 사전·이미지 크기·가격 근거)한 뒤 엑셀에 합쳤다.
